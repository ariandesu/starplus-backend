## Findings for the builder

### T1 — High — The app never shows the generated explanations, and its label is false

*   Nothing reads `explain-cache.json`. "Explain more simply" (`src/app/result/page.tsx`)
    renders the raw `kb.text` under the line "AI-written, reviewed by the developer against
    the cited source." Today that label is false for every entry.
*   **Fix:**
    *   Run `tools/sync-core.sh` so the cache ships in `core/` (update the checksum).
    *   Add a `getExplanation(entryId, level)` helper. It recomputes the key exactly as
        `pregenerate` does (`sha256(id + "\n" + text.join("\n"))` + `:standard+simple:<model>:prompts-v1`)
        and returns text **only if `status === "reviewed"`**.
    *   "Explain more simply" shows the `simple` text, labelled as today.
    *   If an entry is not reviewed (rejected or missing), show the source text **without**
        the AI label, as "From the cited source".
    *   Unit tests:
        *   a reviewed entry returns AI text;
        *   a rejected entry falls back to the source;
        *   an edited source text (changed hash) falls back to the source.
    *   CUJ 5 still passes offline.

### T2 — High — The prompt makes the model drop safety qualifiers

*   `explain-entry.md` says "No status colours or words like 'normal' or 'fine'". That rule
    is meant for judging the reader's own results. The model applied it to "no **normal**
    breathing", the clinical trigger for CPR, in two first-aid entries.
*   The filter cannot catch a dropped word, because it only checks for added ones.
*   **Fix:**
    *   **Prompt:** "Keep every qualifier and condition from the entry word for word,
        including 'normal', 'normally', 'at least', 'no sooner than', 'only if', 'never',
        'do not', 'at once'. The ban on 'normal' and 'fine' applies only to describing the
        reader's own results."
    *   **Filter:** add a must-keep check to `core/explain/filters.ts`. For each protected
        phrase above (word boundaries, case-insensitive) that appears in the source, the
        output must contain it the same number of times or more.
    *   Add the two CPR sentences and the distance sentence to `tools/eval/cases.json` as
        must-reject cases.
    *   Do **not** change `PROMPT_VERSION`: that would orphan the 27 reviewed entries.
        Record the prompt change in `docs/designs/deviations.md`.

### T3 — Low — `pregenerate` loses the whole run on one rejection

*   It throws on the first filter rejection, and only writes the cache at the very end.
*   **Fix:** log the rejection, skip that entry, continue, and write the cache after each
    entry. Exit non-zero if anything was skipped.
